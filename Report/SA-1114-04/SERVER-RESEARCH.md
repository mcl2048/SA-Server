# SA-1114-04 · 服务端研究与边界

基线：`811193a / v0.2.14-LYNX`；2026-11-14 UTC。

- 修改前完整读取任务、新宠注册与区域安装、`attackOnce`、`statusSeq`、`enemyAI`、`automationSkillFactor`、`timid/flee/abduct` 及世界开战入口。
- 本次实际在线读取 [Go 官方 Add a Test](https://go.dev/doc/tutorial/add-a-test)，页面 33842 字节，包含先失败再修复示例。使用 `test-driven-development`、`systematic-debugging` 和完成前验证技能，先用真实命令固定缺少注册／技能退化／AI遗漏。
- 世界和战斗均单一权威：每发重新收集当前合法活敌，不沿用第一发目标或回合开头的死亡状态。物理伤害只调用一次既有引擎，Magic仅表达远程演出。
- 原生 `timid` 能直接驱离，未见头目保护，不能以它证明新技能可对所有目标驱离。`abduct` 用 `NoAbduct` 禁止有NPC或WinFunc的战斗；新技能继续服从该保护，并独立禁止PvP、玩家、玩家宠物和不可捕获的特殊敌人。
- 禁逃楼层只在world层可知，需独立传入新技能的驱离限制，避免改动旧旅程伙伴语义。被免疫的驱离分支保持失败，不改抽麻痹。
- 原生地图二进制证明玄黄的洞窟地下２楼为11202，80×80；(40,40)/(41,40)按原生TileSet规则可走，原区域505、Z1、敌群676/678/680。小区域覆盖保留原敌权重，避免改动整层。
- 五发事件顺序固定：每发Magic保留物理结果与实际守护者字段；驱离成功随后发送既有Flee事件，下一发再选目标。驱离保留HP，不冒充死亡／击飞，不与麻痹同发。

边界与概率最终值在服务端交付报告记录；浏览器、图片、发行与推送由主代理集成，不以Go测试代替实体设备认证。
