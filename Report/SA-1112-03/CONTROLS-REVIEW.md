# 手机控制界面独立复核

## 范围与实现合同

本子任务先只读研究原生 UI，随后按父代理追加分工实现 `client/src/mobile-shell.ts`、新增 `client/src/mobile-controls.ts`，以及对应 `client/test/mobile-shell.test.mjs`。父代理拥有 `main.ts`、`ui.ts`、`mobile-view.ts`、`mobile-position.ts` 和页面布局。本报告不替代父代理的角色、地图、战斗端到端验收。

控件接口为 `navigate(-1 | 1)`、`click(0 | 2)`，选中状态为 `selectedId`、`selectedLabel`。导航只更换可达热区并保持原生 hover；点击交给原逻辑处理，右键保留各业务原语义，不等同通用返回。左键、右键控件不先调用会清空坐标的 `cancel()`。

两种朝向共用八方向摇杆，方向遵循原 MOVE 表。摇杆有中心死区、指针捕获、松手、取消、失捕获、失焦、页面隐藏、模式切换、朝向变化及 `sa-controls-drag` 释放路径。浮动位置模块由父代理实现。可移动控件使用稳定 `data-mobile-control` 标识。

`sa-controls-layout` 仅在首次进入手机版、phase/layout 或主要区域显隐变化后派发一次，且在 inputs/actions 同步后派发。普通刷新与 HP/文字变化不派发，避免打断持续移动。选中项的内部 ID 会通过原 actionLabel 转换为可读名称。

## 真实 Chromium 复核

使用独立匿名浏览器会话，运行时地址从 `/tmp/sa-layout-runtime.json` 读取。只操作登录页及注册对话框的打开/取消；未注册账号、未登录父代理 fixture 账号、未发送注册请求。浏览器采用触屏移动模拟及 SwiftShader，横屏 844×390，旋转至竖屏 390×844。

1. **原生选中持久**：连续三次“下一个选项”后原生 `Ui.hot='ok'`，鼠标逻辑坐标为 `(440,345.5)`。300ms 后 hot 与坐标保持不变，`clickHot=''`，没有自行激活。
2. **可读标签**：选中 `quit` 后右栏显示“清空账号与密码”，不再显示内部 ID。
3. **原生右键语义**：填写未提交假账号和密码后，对 `quit` 发送右键，字段保持不变。注册对话框选中 `dlg-cancel` 后发送右键，四个原输入框仍可见；这与该画面没有原右键关闭处理一致。
4. **原生左键与输入身份**：对 `quit` 发送左键后两个字段清空，焦点返回原账号节点。对 `register` 发送左键打开四个注册输入框。导航到 `dlg-f0` 并左键激活后，原注册输入节点获得焦点。导航到 `dlg-cancel` 并左键激活后，恢复两个登录输入框。DOM 镜像“取消”同样关闭原对话框。
5. **真实游戏画面点击**：登录画面裁切后，按实际 canvas rect 与逻辑 hit 转换出的屏幕坐标 `(504.875,138.9375)` 直接触摸原注册入口，可打开四个原注册输入框，证明触控仍进入原热区路径。
6. **浮动控件可命中**：修复前实测拖出轨道被 `overflow:auto` 裁剪。父代理改为 portal 后，左鼠标键从原矩形 `(691,172.5,145,64)` 拖至 `(347.5,163,145,64)`，位于游戏中央的控件可见，`elementFromPoint` 命中该控件，结束后没有残留 positioning 状态。
7. **保存与朝向隔离**：重载后上述中央位置恢复且仍可命中。切换 390×844 使用竖屏默认位置、未 portal；切回 844×390 恢复原横屏自定义位置且可命中。
8. **重置**：显示重置入口后执行重置，控件恢复 `(691,172.5,145,64)` 并回到原父节点。
9. **多指中止长按**：第一指按住控制键300ms后第二指介入，再等待500ms，未进入 portal/positioning，未出现重置入口。待定长按成功取消。

一次脚本断言失败来自测试字符串超出账号原 `maxLength=16`，实际被截断为 `fixture-unsubmit`，不是点击路由故障。校正后确认左右键业务行为符合预期。

## 裁切边界结论

不应统一裁切所有非地图画面到逻辑 `(80,60,640,480)`：

- CharSelect 的上一页/下一页按钮锚点为 x=50/750，分页标题 y=30，线路名位于 `(8,8)`。
- MakeSelect 的返回按钮锚点为 `(64,520)`；形象菜单位于 x=656，窗口和文字可超出720。
- 多数画面的原 bottomLine 位于 y=580，会被裁掉。

登录页常规输入、确定、清空、注册和找回入口位于美术区域内，可单独采用该裁切；有全局 modal 时恢复完整800×600更稳。其余画面维持完整逻辑范围，除非逐画面重新布置。父代理已选择仅 Login 且无全局 modal 时采用裁切。

## 最后 CSS 窄改与验收边界

- 竖屏模式开关移至游戏高度 `75vw` 之后的状态区域，状态标题留84px右侧空间。
- 横屏菜单设独立滚动与最大高度，避免八个菜单按钮把底部摇杆推到屏外。
