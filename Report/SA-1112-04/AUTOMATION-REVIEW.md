# 服务端离线挂机实施与验证

## 架构与状态

`server/internal/world/automation.go` 将自动遇敌、自动战斗及快速战斗的意图和节奏放在唯一世界协程中。`World.Run` 每 250 ms 调用 `automationTick`；不依赖浏览器动画、定时器或网络心跳发战斗指令。角色实体保存内存态 `autoPlayState`，传输断开不清除，明确登出随实体离开而停止。服务器重启后不恢复挂机意图。

`SetAutoPlay` 接受自动遇敌、自动战斗、快速模式、短暂停及 v2 AI JSON。JSON 最大 16 KiB，版本、治疗百分比、计划种类及目标有验证；非法输入不改变已经接受的状态。`AutoPlayState` 用于同步按钮和停止原因。浏览器状态不包含可采信的生命、位置、回合号或奖励。

自动遇敌调用与手动移动共享的 `w.move`，保留令牌桶、碰撞、队伍跟随、原遇敌概率和原始战斗建立流程。优先在相邻格往返，避开传送点和事件 NPC 所在格；地图变化、没有安全相邻格或耐久不足 20% 时停止遇敌并同步原因。队员不独立移动。服务端自动产生的移动额外回传自己的 `ObjMove`，因为原手动移动广播依赖客户端预判而不回传本人。人物/宠物战斗状态、消耗、经验、石币和掉落仍由原战斗结算处理。

普通面板及聊天的 `paused` 是 2 秒租约，在线客户端需要刷新；标签冻结后租约自然到期，已断开的传输直接忽略租约。NPC 交互窗口、交易、摆摊、查看摊位及观战保留安全暂停；断线处理会清理临时交互。这里的暂停不自动执行 NPC 选项或交易确认。手动移动只停止自动遇敌，不清除自动战斗与快速模式选择。

## 回合与多宠

快速模式每个新回合等待至少 1 秒，普通自动模式等待 4 秒。250 ms 世界 tick、混合手动队员等待和回合检测会带来额外延迟；上述时间不是每秒固定收益保证，也不随客户端演出速度无限缩短。

引擎只为启用自动/快速的角色提交指令。PvP 不执行服务端自动命令；未启用自动的队友仍需自行提交或走原超时流程。公共手动指令在服务端掌握该 PvE 角色时忽略，防止过期浏览器指令与自动引擎竞争；取消自动后可手动操作。

人物与宠物指令复用从原 `BattleCommand` / `BattlePetCommand` 抽出的内部校验方法，不在世界线程内调用会重新 `Do` 的公共方法。宠物按 `ft.petSlots()` 逐一选择及提交，支持当前属于该人物的全部出战宠物。每次宠物提交后检查角色仍在同一场战斗、回合号是否改变；最后一只宠物可能完成已有的人物指令，因此必须阻止旧指令泄漏到新回合。奖励只经原战斗结束路径发放。

## 服务端 AI 与原浏览器 AI 的差异

使用相同 v2 设置字段：治疗阈值、打不过逃跑、进攻精灵、捕获、丢肉，以及人物/宠物首回合和后续回合计划。服务端支持紧急回复、复活、解除匹配异常、补 MP、逃跑、只捕获可捕获的 1 级敌人，及固定攻击/防御/精灵/宠物技能计划。捕获与逃跑优先于固定宠物进攻；捕获优先使用手下留情，否则防御/待机。所有出战宠物使用同一组首回合/后续设置，各自在其实际战斗位置选择目标和合法技能。自动丢肉统一使用原客户端图号范围 24000–24044。

这不是原 `client/src/aismart.ts` 的逐行移植：浏览器 `localStorage` 保存的敌人伤害及技能学习均值未上传，也不参与服务端决策。服务端使用当前可信等级、攻击力、耐久及可用技能作较保守估计；不保证与原浏览器 AI 的具体目标、补血道具/精灵选择、攻击评分、MP 预留或学习后的行为完全相同。服务端回复倾向可用回复量较大的精灵，并没有完整复现原客户端最小足量回复、多目标伤害估值和学习后的威胁排序。自动宠物只隐式选择明确列出的战斗技能，不隐式偷窃、牺牲、变形或离场；玩家明确固定技能仍走原合法性校验。

原精灵群体目标校验仅接收类型 8/11 的 20/21 目标，导致类型 2/3 的原客户端群体指令被转为空行动。本次补上这两种类型；命令入口同时限制类型 2 只能目标己方、类型 3 只能目标敌方，防止修复扩大为错方施法。

## 已执行验证

本节只记录实际执行的 Go 验证，不代表浏览器休眠、移动设备杀进程或正式发布已验收。使用 Go 1.27.3，`GOMAXPROCS=2 GOMEMLIMIT=400MiB`，并行包数 `-p=1`。

- `go test -C server -p=1 ./internal/world -run 'TestAutomation|TestMagic' -count=1`：通过，初次 3.704 秒，最终整理后 6.452 秒。
- `go test -C server -p=1 ./internal/world -count=1`：世界包全量回归通过，44.415 秒。
- `go test -C server -race -p=1 ./internal/world -run '^TestAutomation' -count=1`：12 个自动化测试通过，15.466 秒。之后增加自己的移动回传断言、肉图号统一；这两处在后续普通重点测试中复验，未将前次 race 结果扩大为后续代码的 race 证明。
- 最后执行 `go test -C server -p=1 ./webclient ./cmd/saserver ./internal/world -run 'TestAutomation|TestMagic|TestBuiltRoutes|TestContentValidator|TestMissingBuild|TestLoginArtwork|TestClientGzip' -count=1`：三包通过，分别 0.029、0.018、3.631 秒；包含上述本人移动回传断言与肉图号调整后的自动/魔法验证。

12 个 `TestAutomation*` 测试的覆盖内容如下：

1. 脱离传输后自动击败 1 级敌人，反复运行 20 tick 只得到一次胜利与 1 石币奖励。
2. 单人五只出战宠物均提交，一回合只结算一次且下一回合没有残留指令。
3. v2 JSON 合法输入、非法版本/百分比/计划/目标/超长输入。
4. 脱离传输后自动推进、快速回合最短节奏及过期手动指令拒绝。
5. 已有人物指令、最后宠物触发结算时不向新回合注入旧指令。
6. 在线短暂停、断线忽略短暂停、冻结租约过期、低耐久停止；新增本人移动回传断言。
7. 手动移动只关闭遇敌、停止状态同步及非法设置不改变已接受意图。
8. PvP 不被自动引擎推进。
9. 首回合/后续固定计划，以及捕获覆盖宠物攻击避免误杀。
10. 紧急回血选中原道具，并经原战斗入口实际生效。
11. 全体回复实际治疗人物与宠物、拒绝错方全体施法，以及允许/拒绝的目标类型。
12. 不隐式选择危险宠物技能，及死亡宠物和行目标映射。

## 只读联动复核发现

2026-11-13 复核 `main.ts`、`net.ts`、`battle.ts` 与服务端快照时，已向主整合者提出以下事项，由其负责跨文件修复及浏览器验证：

- `serverAuto` 若直接使用角色自动标志而不排除 PvP/观战，会把客户端手动战斗操作也挡住，尽管服务端明确不自动 PvP。
- 恢复快照若先发 `BattleStart` 再发 `AutoPlayState`，刷新后的客户端可能先用默认快速模式创建错误的战斗界面；自动状态应在场景创建后、战斗快照之前到达。
- 服务端自动丢肉后，旧客户端 `finish` 不应再按旧格位发送 `ItemDrop`，否则有重复或错格删除的风险；服务器与浏览器应统一肉图号判别。
- 明确登出/关闭后若不重置全局 `serverAutoPlay` 与发送签名，而新人物首次进入又不下发自动状态，上一人物的遇敌标志可能泄漏给下一人物，或者界面显示开启但服务端未开启。应清理新世界初值，并以本次服务端状态初始化后才同步意图。当前低耐久停止响应会覆盖客户端 encounter，单看这条停止路径没有发现下一帧自动重开的代码。

同 token 恢复、跨设备顶替、浏览器 UI 联动和最终真实浏览器验收由会话与主客户端任务负责；本报告不把只读复核当成这些流程的端到端通过证明。
