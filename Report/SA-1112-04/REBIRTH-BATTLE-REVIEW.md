# 转生与多宠战斗实现复核

本报告覆盖本次委派范围内的转生逻辑、战斗核心宠物归属、客户端逐宠指令与战斗恢复。配置、GM、世界层多宠分配、离线自动战斗、网络重连及协议生成由主代理与另一位代理负责；本报告只记录已经直接核实的合同和测试结果。

## 转生边界与兼容

- 人物上限调用 `Rules.charMaxTrans()`，宠物上限调用 `Rules.petMaxTrans()`。上限 0 禁止新转生；降低上限只阻止继续转生，不回退已有存档。人物 NPC 显示与最终变更均检查上限，宠物最终确认也检查上限。
- 原人物前六次、宠物前两次计算保留原分支和舍入。人物高等级服务器每次用于原公式的等级贡献仍最多 130；第六次的 620 原总值覆盖、任务统计、属性分配和赠宠保持原里程碑。
- `transMax = 6` 表示原版六转里程碑，不能替换为配置上限。六转赠宠只发生一次。六转以后 NPC 继续要求原六转任务、长老宠与碎片；长老宠可为二转及以上。碎片延续原规则：先检查至少 15 个，随后交出身上全部该碎片。
- `TransEq` 高 16 位累计任务、低 16 位累计等级。第七次起冻结六次历史，并把公式输入限制为最多 120 次任务、780 累计等级，避免高等级长期累加串位。新属性基数仍从六转历史计算：`int(620/12 + quests/4 + (levels-6*85)/4)`，额外收益为 `floor(120*k/(k+12))`，`k = 当前转数 - 6`，始终小于 120；第 100 转增加 106。转后可分配点数仍为 `10*转数`。
- 宠物第三次起不继续应用玛蕾菲雅成长五次方；总成长额外上限依次为 3、2、2、1……，绝对上限 255。随机 ±2 后重新约束总和，避免随机数突破上界或降低正常旧总成长。255 是本次平衡约束，不是存档编码限制；`Alloc` 实际为 JSON `[4]int`。已有超 255 异常宠仅在主动接受第三次及以后转生时规范，不在登录或修改配置时自动改写。
- 第六次以后持续保留六转专用事件，避免额外转生清掉必要剧情里程碑。`TENSEI` 按完整数字标记选择，修复 `TENSEI:1` 误命中 `TENSEI:10`。
- 状态、邮件和交易显示额外转数时使用准确数值；战斗结果只在实际入袋石币大于 0 时显示“获得石币”，窗口增高并上移以容纳奖励行。

## 战斗归属与重排合同

`battle.Fighter` 增加 `OwnerSlot int` 和 `OwnerSet bool`。新世界层构造必须同时设置 `OwnerSet=true`；旧测试和旧构造没有设置标记时仍使用单宠旧规则 `Slot-5`。`Battle.PetOwner(f)` 校验宠物前排、同一阵营、主人后排与玩家身份，无效返回 -1。

`PrimaryPet(ownerSlot)` 作为归属查询，优先选原列且属于该主人的宠物，否则选该主人第一只宠物。召回和换宠另有严格主宠合同：只操作 `ownerSlot+5`，主宠缺席时也不回退选择副宠，不另找空位；该列若被其他主人占据则拒绝操作。这与世界层主宠背包、HP、经验映射保持一致。主人逃跑或被赶走带走所有在场自有宠物；叛逆攻击、惩戒忠诚度、变身、守护和憾甲追加攻击都使用实际主人。敌方怪物原前后排守护、憾甲连带规则保留。

补充修复：先召回主宠（例如位置 5），下一回合重召同一背包宠物时，早先核心错误使用 `PrimaryPet` 回退到位置 6 的副宠，与世界层仍按位置 5 记录的合同不一致。现已固定主宠列，新增回归同时验证重召位置 5、位置 6 副宠的 HP/忠诚度/中毒/蓄力保持，以及主宠列被他人占用时完全不变更战场。

新增 `(*Battle).RemapSlots(mapping map[int]int)`，供世界层重新分配宠物战斗位置时使用：

1. 在两次 `Resolve` 之间、清理或重排 `Battle.F` 之前调用。
2. 参数为旧位置到新位置；-1 或无效新位置表示原引用退场，缺省键保持不变。映射同时应用，支持 `5↔7` 互换，不能按链逐次变换。
3. 只更新核心私有跨战斗者引用：`guardian` 的两端、钻地待发攻击 `earthT`。退场的守护引用删除；退场延迟目标改为 -1，由正常目标调整选择另一个合法敌人。
4. 不改 `F`、`Fighter.Slot`、`OwnerSlot`、`KilledBy`、已提交指令、事件或退场记录。这些仍由世界层处理。
5. 重排现有战斗者应直接移动同一个 `Fighter` 对象，不能重新 `Add`；`Add` 会重置蓄力和击杀信息。附着在对象上的中毒、咒术、蓄力、变身、属性改变、骑宠等效果随对象保留。`foxSave` 保存原形象编号，`varySave` 保存数值与形象，均不是战斗位置引用，不能映射。

## 客户端指令与恢复

- 通过 `BattleFighter.ownerSlot` 与 `bagSlot` 将每只出战宠物映射至自身背包技能资料，不使用传统列号推断主人。
- 手动人物指令后逐只选择宠物技能和目标，可点击宠物标签切换。已提交集合以战斗位置独立记录，每只宠物每回合只发一次。
- `serverAuto()` 为真时，普通画面、快速画面及旧自动决策入口均停止客户端发指令，保留播放和“服务端自动战斗”提示。观战同样不发宠物指令。
- `BattleStart.resume` 恢复原位置、当前回合、异常状态、人物已提交和 `submittedPets`；不重新播放入场、不重新执行首轮客户端 AI。
- `BattleJoin.resetPets` 只重建快照包含阵营的宠物前排。PVE 增援快照不含敌方怪物，客户端保留敌方前排。位置变动后的技能记忆和已提交记录按背包宠物身份迁移，避免误套到新占位宠物。
- `PetOut` 使用事件自身的 `ownerSlot` 和 `bagSlot`，避免 `Pets.battle` 尚未同步时选中旧主宠技能。协议与世界层必须填写这两个事件字段。
- 新增同步公开接口 `setQuick(on: boolean): void`，同一战斗对象可即时切换普通/快速显示。切换不重建战斗者、不清回合、不清已提交记录、不丢排队演出；快速转普通时按原战场编号延迟加载背景且只加载一次，保留快进后的动画时间并换算剩余指令期限。决斗和观战禁止切到快速显示。
- 快速显示不等于客户端自动指令开关：`quickFrame` 与 `autoCommand` 都检查当前 `host.auto()`，关闭实时自动开关后不会因开战时曾经为快速显示而重新发送旧客户端自动指令。主代理应让 `host.auto()` 读取实时设置，并在模式切换时同步画面、音乐和结束回调；不能捕获开战时固定 `quick` 值继续驱动自动战斗。

## 数据与集成核对

- 原 `ten.arg` 的第五次对话不写具体转数，作为第六次及以后回退文本可复用。
- `jobdaily_h5.txt` 的 9101、9102 原提示固定 `TRANS<6`，主代理需按配置上限调整提示门槛。
- `eden3/rider.arg` 和 `family/rider.arg` 原机暴领取条件只允许 5 或 6 转，额外转数需要主代理兼容；不建议全局改变 `TRANS` 比较语义。
- `ler1.arg` 的 `TRANS=5` 只在某个“力量收集未齐”提示分支，真正任务接取条件不含该限制；不需要泛化整个剧情。
- `maxGold` 在五转以上已有固定钱包上限，宠物仓库容量也有既有上界，不随额外转数继续放大。原骑乘对转生宠物的独立限制保持。
- 世界层重排还必须迁移其提交指令、技能命令、击杀分配与实际宠物背包映射；`RemapSlots` 有意不重复处理这些公开记录。完整世界层回归和浏览器实测由主代理汇总。
