# v0.2.9-LYNX · 数据可靠性与多角色探索

## 玩家可见变化

| 功能 | 行为 |
|---|---|
| 登录 | 密码认证进入大厅，不抢占本账号其他角色 |
| 角色选择 | 显示在线或后台挂机状态；选择已运行角色时恢复实时数据，而非重读旧存档 |
| 切换角色 | 返回选择页不结束旧角色的服务端自动战斗；新角色可以独立进入游戏 |
| 退出账号 | 撤销当前浏览器凭据，后台角色继续保留；停止挂机应关闭自动遇敌、自动/快速战斗 |
| 同角色接管 | 只接管明确选中的角色，旧连接被隔离；其他角色不受影响 |
| 四位机械神宠 | 与佩露夏同档149成长预算，按辅助/坦克/速攻/突击分配；旧宠物保留培养差异 |
| 战斗数字 | 深底高对比血量卡、明确当前/上限数字，手机加大血量和伤害字体 |
| 小地图 | 配置全开，点击目标自动绕障；不可达目标明确反馈，斜角不能穿墙 |

## 管理员配置

```yaml
# 顶层字段，只接受整数0或1；需要重启服务器生效。
minimapReveal: 0 # 0保留原探索显示，1显示完整当前楼层
```

全开不改变角色探索记录；地图分块加载。点击当前楼层地图规划八方向路线，手动方向输入可以取消。自动路线不会把传送点作为普通中间格；若目标需要跨地图，先选择传送点。障碍、地图范围、步速与当前位置继续由服务端验证。

恢复令牌存于标签页 sessionStorage，密码不存储；旧版 localStorage 共享令牌不再使用，升级后需要一次密码登录。关闭页面后角色仍驻留服务器；服务器进程重启后令牌与自动行为不补算，玩家重新认证并选择角色。

## 持久化与部署

- SQLite 保留单连接写入，使用 WAL、FULL 同步及 IMMEDIATE 事务；启动确认实际 WAL 模式，不以增加连接数冒充多写者吞吐。
- 表结构升级、留言编号分配/裁剪、邮件容量与取删操作增强原子性。数据库路径按文件名转义，避免 `?`/`#` 改写连接参数。
- 邮件收件索引、活跃排行索引减少查询扫描；后台角色不再计算没有浏览器消费者的视野差分，重新接入完整重建；切换角色释放旧Field网络监听器及地图缓存，避免长期切角累积资源。
- 旧经验转换的所有角色更新与完成标记在同一事务提交，中途失败不会留下部分转换；历史版本已经发生的部分转换不能自动推断修复。
- 正常部署仍须 SIGTERM 停服并等待保存完成。备份应使用 SQLite 一致性备份方式；不要只复制活跃的 `.db` 而丢弃 WAL。不要将 WAL 数据库放到网络文件系统或多个游戏进程共享同一数据库。
- 本批没有追加美术素材；保留 `update/install-ai-pets.sh` 和既有包供新装部署。二进制、客户端与游戏数据一起更新，切勿混用旧客户端与新协议。

## 交付与复现

运行 `bash scripts/build-linux.sh` 生成内嵌匹配网页的静态 Linux AMD64 程序和摘要；`python3 scripts/package-linux.py` 创建不含运行时Assets、数据库、凭据或本机配置的发行zip。完整基础Assets仍需单独提供。

专项记录位于 [SA-1113-02](../Report/SA-1113-02/INTEGRATION.md)，最终测试、浏览器范围与SHA以 [最终验收](../Report/SA-1113-02/ACCEPTANCE.md) 为准。真实Chromium触屏视口不代表实体设备/Safari认证；SQLite单机可靠性提升不等于多节点高可用或端到端邮件exactly-once。
