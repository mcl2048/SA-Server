# 验证与增量发行

## 八向与逐帧

记录每方向源图尺寸、显示缩放、主体高度、足底世界坐标；源图纵横比例和转向体积分别验证。专门检查默认战斗方向、左右侧面和背面。不能把“等比例缩放”误当成“转向体型一致”，也不能把“所有帧不同”误当成“跑姿正确”。

图集要求：非空alpha、所有帧在画布内、关节无漂浮碎片、无旧腿残像、动作ID／ticks／事件不丢失。透明边压缩和图集重排需独立还原逻辑帧，核对锚点。阴影检查放在低于身体的固定地面坐标，加入起跳／受击旋转关键帧。

制作八向静止对照、跑步完整循环与攻击分解图。用同一原生世界尺度对比原生参照、上一版本和新版本。用户截图可用逐帧匹配区别旧包；相关分数辅助定位，不能单独认定远端版本。

## 真实运行

以匹配最终客户端的Linux程序和真实资源运行，通过原生UI／允许的GM请求触发业务；只读采样方向、动作、当前帧、图集来源和绘制矩形。测试脚本不要注入假战斗或修改页面业务对象来制造通过。

本项目常见八向为S、SW、W、NW、N、NE、E、SE；常用己方默认dir3、敌方dir7，仍应读当前实现核实。核对两侧默认待机、跑向目标、命中、回位和待机恢复。转屏、缩放时绘制宽高比保持一致，脚底与影子关系正确。移动视口／触屏模拟不等于实体Android、iOS或Safari认证。

若使用私有测试数据或账号，凭据、数据库和运行日志留在私有临时目录；截图避免账号密码和认证画面，报告仅放必要证据。

## 图包和安装器

- 新素材用独立版本目录；保留宠物和图像编号以免迁移存档。客户端明确选择新目录，不能以保留旧目录代替升级验证。
- 源素材树与运行数据库通常不入Git；按仓库规则分发独立图包、逐文件清单及Shell/Python安装器。版本号与是否构建ZIP遵循当前任务，不能把历史版本硬编码成通用要求。
- 安装器先检查新包摘要、精确文件白名单、目录、路径和链接，再暂存、fsync、原子发布和复核。用户授权清旧时，按旧发行清单识别，完成新包后才移除旧包；既有新版的重复执行也应完成旧包清理。
- 损坏新包、现有新版冲突时不删旧包；旧目录中未知／修改／链接保留并报错。覆盖新装、跨版本、部分已知残留、重复安装不改mtime、自定义Assets目录及失败不误删等真实行为。
- 清理旧目录不会改变旧进程或已加载网页；升级需匹配程序、外部client目录（若有）及刷新。停服重启仅在已有授权范围内执行。

验收最终程序版本、资源HTTP内容、图包摘要和ZIP内文件一致；适当跑客户端／服务端现有回归。提交前检查路径、凭据及用户数据不会随包公开。报告区分“代码已改”“包已生成”“已在隔离实例验证”“生产已部署”，不混用。
