# 导航、战斗策略与素材联调

仅在当前任务涉及StoneAge自动化或战斗播放时阅读；按用户本轮要求确定功能范围。

- 快速战斗仍绘制地图且执行Field.update。保留路线必须同时暂停发送移动；单纯删除BattleStart的target清空会触发服务端PosCorrect并再次丢路线。战斗结束恢复时重置路径重试计时，普通战斗、换地图、手动输入仍按各自规则取消。从小地图打开大地图后，等待中性pointer帧再接受地图点击，避免打开按钮的同一次按下／释放穿透为新路线。
- 原生InputBox由移动shell采用同一DOM节点。显式inputLabel便于地图坐标／关键字可访问标签；关闭、换页、切场景移除，IME确认不应冒泡成聊天发送或游戏快捷键。用真实桌面和触屏模拟检查输入生命周期。
- 自动化服务端是权威执行者，客户端fallback与UI描述需一致。恢复物品按原生使用函数／参数判断，不能仅凭说明中出现“气力”认定会补MP；肉优先与恢复比例需以真实消耗和资源变化证明。
- 自动逃跑按本场实际escape失败事件计数，第三次后连危险逃跑／无捕获目标逃跑也要抑制，避免无限逃跑。新战斗重置。关键字丢弃用字面包含、忽略空段并排除装备及交易等占用；别引入正则或把空段解释为匹配所有。
- 原作合击与连击不同：多人coattack需要独立组标识，普通combo只能合并同一行动者的连续攻击。动画可同时移动，但服务端HP快照必须按权威事件顺序应用，避免不同图集命中帧导致旧HP覆盖新HP。
- 合击规则研究保存来源与原作代码位置；行动顺序相邻不等于固定敏捷差。不能凭玩家经验杜撰额外伤害倍率。真实观测普通攻击合击、特殊技能不合击与快速播放，并保留死亡、反射、骑乘等服务端边界回归。
- 火炮动作以肩关节变换整个炮臂，炮口世界位置从同一变换计算。绕炮管中心轻转加独立方向特效会产生手臂不抬、炮焰脱离。逐向预备／瞄准／开火／收势与实际战场都要检查。

验收旧角色数据路径时注意已有交互契约：记忆中的“攻击”会自动打开目标框，已有`t-*`时直接选目标，再点攻击会把选择关闭。相簿追加宠物会移动末页边界，使用当前原生页按钮有界查找编号，避免假定从首页翻一次上一页就能找到特定新宠。自动化应等待实际DOM／命中框状态，不能用固定160ms断言未完成的UI转换。

FieldScreen与BattleScreen拥有不同的窗口树。验收脚本须在入战前缓存原生宠物技能槽等场景资料，战斗中读取实际战斗命中框与服务端事件；不能把地图菜单结构当作全局稳定接口。脚本失败与业务失败分别留存，修正脚本后仍须完整重跑目标设备路径。


## 挂机资源与时序

纯展示优化放在构建消息之前，并逐条核对函数是否还承担权威副作用。背包／宠物序列化和存档、奖励／培养结算、任务事件不能随离线跳过；本角色状态无需投影时，在线队友仍可能需要其HP。接管必须用最新状态重建，不回放旧快照。用隔离基准区分在线和离线展示，并报告分配；消息构建减少多少不能推断整服CPU／内存比例。

复用主宠决策时核对所有提前返回分支，尤其显式逃跑仍须选择防御；已有手工人物指令时宠物应依据实际指令重新选择，已提交宠命令不能覆盖。三次逃跑上限要覆盖优先／危险／捕获无目标等全部入口，只按本场实际失败事件计数。

野外恢复和战斗恢复的原生效果可不同。若任务要求挂机整备，复用原生field效果、扣叠和保存，明确参与宠物、优先级、阈值0与物品Field范围；排除负副作用。整备先于战后丢肉／濒危停止，地图改变撤销遇敌必须先于任何消耗。限制每tick消耗并节流，尊重编辑暂停租期、窗口与物品事务；无补给仍执行安全停止，不制造无限资源。

实际离线验收可用CDP冻结真实Chromium页面，从只读SQLite观察奖励增长；关闭此角色所有页面后，观察两次独立保存收益增长，再用原生密码登录／接管核对。区分连续运行、正常SIGTERM保存和进程重启：内存挂机意图与恢复令牌不自动跨重启，停服收益不补算。受控敌群只在私有fixture追加，不能声称自然刷怪或生产认证。

## 地点目录与按需寻路

地点从加载后的有效Game.Warps／LS2MAP派生，避免照抄攻略坐标。合并相邻同目的地入口但保留全部入口格，多目标搜索选可达边缘，不能只取可能需先跨warp才能抵达的中心格。条件入口仅标记，Free／任务资格仍由服务端判定。无效目的地、墙格和同图传送按产品范围过滤；当前数据统计不等于所有私服资源都齐全。

地图请求可优先目标块、起终点走廊，再扩大绕路，保留全图不可达兜底、并发上限与有界重试。未知始终阻挡，保留墙角、非目标warp、快速战斗暂停恢复和手动取消。A*优化同时测直线、对角、绕障与不可达；整数heap decrease-key避免旧重复项，明路快捷返回前逐格检查可通行及最短代价。用独立BFS差分混合未知／墙／warp／多目标，性能结果保留中间退化候选。

移动地点按钮可用原生热区完整label，桌面裁切不影响可访问名字。真实跨图验收需观测实际Move、EnterFloor并确认零PosCorrect，不能只看target已设置。测试驱动等待下一稳定原生帧再选择菜单／命中框；敌方ownerSlot默认0不能被误算作本方宠物，需同时判定阵营。

嵌套可选协议值须验证真实Go omitempty的零坐标。生成器若不递归处理optional对象，入口x=0／y=0会变undefined；检查真实wire经fillDefaults后是否仍可寻路，不能只用显式{x:0,y:0}的理想对象测试。

FREEMORE的ToFloor可能只是同层fallback。目录需要读取FREE／TO各有效分支，复用原生解析与最多10个目的地的规则；同一源格可列多个目标，统计称入口与目的地对应关系。点击只能导航至源格，实际分支仍由服务器条件／随机选择，不能保证选中名称即强制对应分支。


## 当前场景 NPC、目录排版与分帧规划

- “当前场景”按角色实际floor界定；洞窟不同楼层不聚合。前端不请求历史区域人物，换层释放旧NPC列表且忽略迟到响应；服务端非当前层返回空NPC并跳过实体遍历。静态Places可独立按World生命周期缓存，NPC始终读取实时实体，过滤隐藏、空名及越界，重名用坐标稳定排序。
- 地图可见时按需更新NPC快照，保留在途请求上限与超时，勿新增全世界扫描／常驻后台轮询。移动运输人物的坐标有时效，不把最近快照宣称为预测追踪。统计最大当前层人物数及完整协议字节，区分离线审计全集与产品单层请求。
- NPC目标优先精确可走格；墙格／warp占位才选择可达相邻普通格，显示实际停靠位置，不为导航触发自动对话或入口。源对象与floor都要匹配当前服务端快照，未知目标加载后仍需处理墙／portal结果。
- 目录用实际文字宽度换行、较小字号与内容高度分页；地点、NPC及历史区域都须验证完整名称，而非只有aria标签完整。缓存排版到源数组／楼层变化；保留坐标、条件说明和可触碰热区。真实资源外再用多页长名称夹具验证不丢条目。
- 主线程大图A*采用可中断切片，在节点扩展预算后yield；同步版本只用于独立正确性／性能对照。地图修订若发生在搜索中，失败要对新修订重试；每步仍校验。取消、新点击、手动方向、战斗、换层都释放旧搜索，普通地面点击不能复活旧目标。
- 有界工作量不是硬实时保证；分别报告总CPU、每片最长耗时及让出的帧数，不把分帧宣称为总工作量必降。独立BFS差分验证最短代价和路径合法性；失联加载给明确超时与手动重试，快速战斗暂停不误计等待时间。原生pointer桥必须同时验证主指针及button=0，右键／中键／笔侧键不能触发目的地。
